# 🎾 손 테니스

웹캠 앞에서 팔을 휘둘러 치는 **Wii 스포츠 테니스 스타일** 웹 게임이에요.
손 인식은 [MediaPipe Hand Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker)(오픈소스), 화면은 [Three.js](https://threejs.org/)로 만들었어요. 설치 없이 브라우저에서 바로 돌아가요.

## 하는 법

달리기는 캐릭터가 알아서 해요. **공이 오면 팔을 휘두르기만** 하면 돼요.

| Wii 리모컨 | 손 테니스 |
|---|---|
| 휘두르기 | 카메라 앞에서 손(팔)을 빠르게 휘둘러요 |
| 일찍 치면 크로스, 늦게 치면 반대쪽 | 똑같아요. 공이 가장 알맞은 지점에 왔을 때 휘두르면 정면으로 가요 |
| 세게 휘두르면 강타 | 손이 빠를수록 공도 빨라져요 (최고 속도는 km/h로 표시) |
| 탑스핀·슬라이스 | 아래에서 위로 쳐올리면 탑스핀, 위에서 아래로 깎으면 슬라이스 |
| 서브 | 손을 위로 휙 들어 토스 → 공이 내려올 때 내려치기 |
| 메뉴 선택 | 손을 버튼 위에 0.9초 올려두면 눌려요 (마우스도 돼요) |

- **CPU 대전**: 단식, 1·3·5게임. 난이도는 쉬움·보통·어려움·**매우 빠름**(공 약 120km/h)·**말도 안 되게 빠름**(약 180km/h, 서브는 더 빨라요) 5단계예요. 빠른 두 단계는 CPU가 공을 높은 곳에서 치고 탑스핀으로 내리꽂고, 내 선수도 더 빨리 뛰어요. 점수는 15-30-40-듀스-어드밴티지, 서브는 두 번(더블 폴트 있음).
- **연습**: 볼 머신이 보내 주는 공을 몇 번 연속으로 받아넘기는지 세요. 공 속도는 느림·보통·빠름·**매우 빠름**(약 120km/h)·**말도 안 되게 빠름**(약 200km/h, 공이 0.5초 만에 와요) 5단계예요.
- 처음 한 번 **손 맞추기**에서 팔을 3번 휘두르면 내 손 속도에 맞춰 감도가 자동으로 잡혀요. 메뉴의 감도 − ＋로 더 조절할 수 있어요.
- 카메라가 없으면 시작 화면에서 **터치패드** 또는 **마우스·키보드**를 골라요.
  - **마우스·키보드**: 스페이스를 **꾹 누르면 파워 게이지**가 0→100%로 차오르고 다시 줄어들어요. **떼는 순간의 값이 파워**라서, 가득 찼을 때 공이 오는 타이밍에 맞춰 떼야 가장 세요. 서브는 스페이스로 토스 → 다시 꾹 눌렀다 떼기. ↑ 누른 채 떼면 탑스핀, ↓는 슬라이스. 게이지는 메뉴의 "파워 게이지" 스위치로 끌 수 있어요(끄면 스페이스를 누르는 순간 바로 쳐요). 마우스를 휙 휘둘러도 쳐요.
  - **터치패드**: 탭(클릭)하면 치고, 휙 쓸어도 쳐요(빠를수록 세고, 위로 쓸면 탑스핀, 아래로 쓸면 슬라이스). 두 손가락 탭은 슬라이스. 게임 중엔 포인터가 잠겨서 커서가 숨고 끝없이 쓸 수 있어요. `Esc`로 풀면 일시정지돼요.
  - 공통: `Esc` 일시정지, `M` 소리.

## 실행

**바로 해보기**: GitHub Pages 주소로 들어가요 (카메라는 https 주소나 `localhost`에서만 쓸 수 있어요).

**내 컴퓨터에서 켜기** (Windows): `시작.bat`을 더블클릭하면 파이썬 내장 서버가 열리고 브라우저가 떠요. 직접 하려면:

```bash
python -m http.server 8765
# 브라우저에서 http://localhost:8765/ 열기
```

필요한 것: 웹캠, 최신 Chrome 또는 Edge, 인터넷 연결(처음에 손 인식 모델 약 8MB와 Three.js를 내려받아요).
카메라 영상은 브라우저 안에서만 쓰이고 어디로도 전송되지 않아요.

## 어떻게 동작하나

```
웹캠 ─▶ MediaPipe 손 랜드마크 21점 ─▶ 손바닥 중심의 속도(손 크기 단위) ─▶ 스윙 감지(최고 속도 시점·세기·방향)
                                                                        │
공의 궤적을 미리 계산해 "칠 자리와 시각"을 정함 ◀── 카메라 지연(약 0.07초) 보정 ◀──┘
        │  스윙 시각 − 칠 시각 = 타이밍 → 좌우 방향·길이·실패 여부
        ▼
   공 물리(중력·스핀·바운스·네트) ─▶ 규칙 판정(인·아웃·폴트·에이스) ─▶ 점수
```

| 파일 | 역할 |
|---|---|
| `core.js` | 화면과 무관한 로직: 공 물리, 타구 계산, 점수·규칙 판정, 스윙 감지. Node로 테스트 가능 |
| `hands.js` | MediaPipe 손 인식 래퍼 (GPU 우선, 실패하면 CPU) |
| `audio.js` | 효과음 (WebAudio로 합성, 파일 없음) |
| `game.js` | 3D 장면, 선수, 경기 진행, 메뉴, 입력 |
| `index.html` | 화면 뼈대와 스타일 |
| `test/core.test.js` | 코어 로직 테스트 |

테스트:

```bash
node test/core.test.js
```

## 카메라가 안 열릴 때

`NotReadableError`(카메라가 열리지 않아요)가 뜨면 줌·팀즈·카메라 앱, 카메라를 쓰는 다른 탭을 닫고 다시 눌러 보세요.
그래도 안 되면 자동으로 다른 카메라를 시도하고, 그것도 안 되면 화면에 카메라 목록이 나와요. 거기서 직접 고르면 돼요(노트북엔 윈도우 헬로용 적외선 카메라가 같이 있는 경우가 많아요). 고른 카메라는 기억해요.
`NotAllowedError`는 브라우저에서 카메라 권한이 막힌 거라, 주소창 왼쪽 자물쇠에서 카메라를 "허용"으로 바꿔야 해요.

## 알아 둘 점

- 웹캠은 보통 초당 30프레임이라 아주 빠른 휘두르기는 손이 번져서 놓칠 수 있어요. 휘두르다 손이 사라져도 직전 속도가 충분하면 스윙으로 쳐 줘요.
- 카메라 지연은 `?lat=0.1`처럼 주소에 붙여서 바꿀 수 있어요(기본 0.07초). 공이 늘 "빨랐어요"로 나오면 값을 줄이고, "늦었어요"로 나오면 늘려 보세요.
- `?cpu=1`을 붙이면 손 인식을 GPU 대신 CPU로 돌려요.
